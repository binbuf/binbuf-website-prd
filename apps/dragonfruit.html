System architecture

Dragonfruit’s Rust compositor decides where windows go. Its Qt Quick shell draws the Dock and menu bar. Follow a frame from Files to the display, or a volume change from the shell to PipeWire. Select a component to see who maintains it and what it does.

  1. Application Layer Files browses your folders. System Settings edits desktop and device preferences.
  2. Desktop Shell Dragonfruit Shell draws the Dock, menu bar and Control Center. The Files desktop process draws the icons beneath your windows.
  3. UI Framework Qt Quick renders controls described in QML. Qt Wayland connects first-party application windows to the compositor.
  4. Desktop Platform The session entry starts the desktop. Dragonfruit services handle menus, app discovery, preferences, notifications and wallpaper. XDG Desktop Portals and the Dragonfruit backend provide file and screen pickers.
  5. Windowing System Dragonfruit’s Smithay-based Wayland compositor places windows and routes input. A private protocol connects the shell, libinput and libseat provide input and seat access, and Xwayland serves X11 applications.
  6. Graphics Subsystem The native renderer draws with OpenGL ES. EGL and GBM supply contexts and buffers, with Mesa providing drivers on the reference graphics stack.
  7. System Services D-Bus carries requests and Dragonfruit’s system-status service connects desktop controls to host services. PipeWire and WirePlumber route audio, NetworkManager and BlueZ handle connections, UPower reports battery state, UDisks2 manages drives and polkit checks permissions.
  8. System Runtime systemd supervises the session, logind tracks seats, udev announces devices and glibc provides the C runtime.
  9. Operating System Kernel Linux schedules processes and manages memory. DRM/KMS presents frames, evdev exposes input and kernel drivers communicate with devices.
  10. Hardware Platform The CPU and memory run applications. The GPU and display present each frame, while the keyboard, pointer, audio devices, radios and drives carry input and output.

Where the design pays off

Coordinated motion

The compositor knows each window’s position and destination. Overview can move the live windows while the Dock reflects the same window state.

A recoverable shell

If the shell restarts, the compositor keeps your applications mapped. Your Dock and menu bar can return without asking you to reopen your work.

One source for each setting

Desktop preferences live in settingsd. Device state comes from the host service that controls it, so a volume change made in another app can appear in the same slider.

Daily-driver validation on reference hardware is still in progress.

Contributing

Help build Dragonfruit.

A useful contribution can be as small as a clear bug report, a keyboard fix, or a correction to the design docs.

Read the contributor guide

Report a bug

Include your distribution, how you started the session, and the shortest steps that reproduce the problem.

Propose a change

Read the design record for the area you want to change. Open an issue for new surfaces, protocol changes, and cross-component work.

Submit a focused fix

Keep each pull request to one concern. Run make verify-fast and describe what you tested.
